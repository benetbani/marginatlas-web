## 2. What the map shows, stated as findings

### F1. The entry point sends every session to the two most abandoned directories

`CLAUDE.md`'s "Read these first (in order) for any session" list names
`docs/design-system/GUIDELINES.md` as *"authority for any UI work"* and
`docs/architecture/README.md` as the domain map. Measured:

| Directory CLAUDE.md prioritises | Files | Last touched | Age at 2026-08-19 |
|---|---:|---|---:|
| `docs/design-system` | 4 | 2026-06-15 | **65 days** |
| `docs/architecture` | 1 | 2026-05-27 | **84 days** |

Against them, the directories that actually moved this week are `docs/loop` (22
files, today), `docs/brand` (44, two days), `docs/superpowers/plans` (91, today).

**This is the single highest-value organisational defect in the repo.** It is not
that stale documents exist; it is that the one file every session is told to read
first routes attention *toward* them and away from what is live. A new session
follows the instruction, reads an 84-day-old architecture note, and forms its
model of the project from it.

### F2. `plans/` is 86% archive, and its name says otherwise

91 files. By filename date: **78 are from 2026-06**, 14 from 2026-08, 1 from
2026-05. A single month's burst accounts for six sevenths of the directory.

A directory called *plans* reads as forward-looking. Eighty-eight percent of it
is history. A session searching for "the current plan" has 91 candidates and no
structural signal separating the seven that might be live from the seventy-eight
that are finished.

### F3. The repo does not distinguish a RULE from a RECORD, and root proves it

`PLAN_V3.md` and `PLAN_V4.md` sit side by side at the root. So do `DESIGN.md`,
`DESIGN_STATE.md` and `BRAND.md`, alongside two files that are research *prompts*
rather than research or rules. Nothing in the filesystem says which of these
binds behaviour and which merely records what somebody once thought.

Same shape one level down: `docs/handoff` holds **33 records**, which is correct
for records, but `CLAUDE.md` promotes one of them to a rule with *"IS THE CURRENT
HANDOFF, READ IT FIRST"* — and names the 2026-08-01 file while
`HANDOFF-marginatlas-2026-08-18.md` exists. **A record promoted to a rule goes
stale the moment the next record lands**, which for handoffs is every session.

Note the partial cure already present: `docs/handoff/INDEX.md` exists. The
mechanism is there; the entry point bypasses it by hardcoding a filename.

### F4. `docs/loop` is the one directory that already solves this

It separates the four kinds cleanly, and it is the only place in the repo that
does:

| Kind | File | Property |
|---|---|---|
| RULE | `00-OPERATING-RULES.md`, `01`–`10` steps | changes rarely, binds every tick |
| STATE | `STATE.md` | exactly one file answers "what is true right now" |
| RECORD | `WAKE-UP.md` log, `artifacts/` | append-only, never mistaken for a rule |
| OPEN | `DECISIONS-NEEDED.md` | questions, not answers |

**The proposal should generalise this pattern outward rather than invent a new
one.** It is already load-bearing, it is two days old, and it survived a session
gap intact.

### F5. Two repositories, and the boundary is not documented anywhere a session reads first

`E:\atlas` is the data pipeline, is on branch `p4-seam`, and **has no git
remote**. `E:\atlas\website` is the product, is on `main`, and pushes to
`github.com/benetbani/marginatlas-web`. The Bash CWD resets to the parent, so
every unprefixed command inspects the wrong repository.

This is recorded in `docs/loop/00-OPERATING-RULES.md` and in the masterplan error
ledger, both of which a session reads *after* `CLAUDE.md`, which does not mention
it. It cost this session one wrong-repo `git remote -v` on 2026-08-19.

## 3. Blind spot, stated

**A file map cannot distinguish a document nobody reads from a document everybody
relies on.** Git mtime measures writing, not reading. `docs/architecture/README.md`
has not been *edited* in 84 days, which is consistent with two opposite stories:
it is abandoned, or it is correct and stable. The reason F1 still stands is not
the age by itself, it is the age *combined with* the fact that the live design
authority provably moved elsewhere (`docs/brand`, the charter, the 2026-08-19
masterplan) while `CLAUDE.md` kept pointing here.

Where the distinction cannot be resolved, the proposal must **archive rather than
delete**, and leave a pointer.

Reference counts have the same limit: they see imports and links, never the
reading a person does before a decision.
