# Pipeline 2: Sonnet Data-Fill Loop (2026-06-12)

> The machine that turns Fable's blank templates into filled, trustworthy pages at scale.
> Fable owns design and structure. Sonnet owns data and replication. The design-system and the
> Fable-produced templates are the shared contract that neither side may break.

---

## 1. Role and mandate

Pipeline 2 (the Sonnet loop) has exactly one job: take a finished Fable template for a given
page type and a target (a country, city, industry, business category, neighborhood, or
combination) and produce a filled page -- real validated data in every field that can have it,
and labeled placeholders in the fields that cannot.

It does NOT redesign. It does NOT add new sections. It does NOT rearrange component order. It
composes Fable's templates with the Atlas data layer (Supabase, the cost engine, the
extrapolation layer, the `src/lib/` domain functions) and with lightly written Atlas-voice copy
for the narrative fields. The output is a Next.js page file and, where needed, seed data
committed to the appropriate data source.

Fable is the architect. Sonnet is the cartographer who fills in every coastline, river, and
elevation mark.

---

## 2. The division of labor (Fable vs Sonnet)

| Concern | Fable (design pipeline) | Sonnet (data pipeline) |
|---|---|---|
| Section structure and order | Owns entirely | Never modifies |
| Component choice and props shape | Owns entirely | Reads as spec, never overrides |
| Design tokens, colors, motion | Owns entirely | Never touches |
| Voice register and brand | Sets the standard | Follows it faithfully |
| Copy for narrative fields | Seeds the pattern | Writes at scale, same register |
| Real data: margins, wages, startup costs | Provides one worked example | Fills across all targets |
| Labeled placeholders | Sets the convention | Uses the exact convention |
| New page types | Prototypes in Fable first | Replicates after prototype is approved |

The shared contract is the template file and the prop types. Fable ships a template with
clear prop boundaries and placeholder conventions. Sonnet fills those props. If Sonnet
needs a structural change (a new section, a different component), it flags the need to Fable;
it does not self-modify the template.

---

## 3. Unit of work

One iteration of the loop processes exactly one (page-type, target) pair. A target is the
minimum unit that produces one URL:

- Business page: `(industry_slug, place_slug)` -- e.g. `(restaurants, lisbon-portugal)`
- City page: `(city_slug)` -- e.g. `london-uk`
- Country page: `(country_iso)` -- e.g. `DE`
- Industry page: `(industry_slug)` -- e.g. `bakeries`
- Neighborhood page: `(neighborhood_slug, city_slug)` -- e.g. `(marais, paris-france)`
- Learn page: `(article_slug)` -- e.g. `how-much-does-a-cafe-make`
- Compare page: `(slug_a, slug_b, type)` -- e.g. `(london-uk, paris-france, city)`

The loop iterates over a **target catalog** (Section 7). Each iteration is self-contained:
read the template, resolve the data, validate, write the output. No iteration depends on
another's output.

---

## 4. Input specification

Each iteration receives two inputs:

**Input A: the Fable template**
A Next.js page file (`.tsx`) produced by the Fable pipeline. It is a valid, renderable page
with:
- All structural sections in final order.
- Components imported from `src/components/`.
- Props passed as typed constants from `src/lib/` accessors (or clearly marked with the
  `FILL:` placeholder convention defined below).
- No raw hex/px values (tokens only, per the hard constraint).
- No em-dashes in user-visible copy.

The template represents "what a perfect page of this type looks like, with one worked example."
It is the canonical reference for what the filled page must match structurally.

**Input B: the target descriptor**
A small JSON object with the minimum routing keys for one target:

```json
{
  "page_type": "business",
  "industry_slug": "restaurants",
  "place_slug": "lisbon-portugal",
  "country_iso": "PT",
  "place_type": "city"
}
```

The descriptor is generated by the catalog builder (Section 7) and stored in
`scripts/pipeline/sonnet/queue/`. One file per pending target.

---

## 5. Output specification

Each iteration produces:

1. **The filled instance data, never a hand-authored page file.** Every Fable template is a
   single parameterized `page.tsx` that reads instance data via `generateStaticParams` plus a
   data-fetcher. Sonnet never writes or edits a `page.tsx`; it writes the data that the existing
   parameterized template renders. This is the lane boundary the `verify_pipeline_lanes.ts` gate
   enforces (design vs data). The output lands in exactly two buckets (the shared handoff write
   set, identical to pipeline-fable.md section 8):

   - **Editorial copy bucket** (`data/editorial/<page-type>/<slug>.json`): the contract-shaped
     narrative slots (honestTake, plainTerms, gutCheck, and the rest), one file per target.
   - **Page-data bucket** (`data/seeds/<page-type>/`, Supabase `cells` upserts, `content/blog/`
     front matter, and the narrow pre-existing accessors): the numeric and structured data the
     template binds to.

   By page type:

   - **Business / cell pages:** the page is already parameterized via Supabase `cells` rows.
     The output is a validated Supabase row upsert (JSON payload) plus the editorial copy file
     in `data/editorial/business/<slug>.json` (or, where the repo still resolves copy through
     it, an override in `src/lib/content/narratives.ts`). Sonnet writes data, never a page file.
   - **City / country / industry pages:** static routes, each driven by one parameterized Fable
     template. The output is a data-seed JSON in `data/seeds/<page-type>/` plus the editorial
     copy file. Sonnet never authors a per-target `page.tsx`; if a target needs a structural
     change, that is a contract gap (section 12, Rule 1).
   - **Neighborhood pages:** data-seed JSON for `src/lib/cities/neighborhood_flavor.ts` (a
     pre-existing accessor in the page-data bucket) or the neighborhood Supabase table, plus the
     editorial copy file.
   - **Learn pages:** the filled Markdown + front matter in `content/blog/`.
   - **Compare pages:** a data-seed JSON in `data/seeds/compare/` consumed by the compare
     page's data resolver, plus the editorial copy file.

2. **A fill-report** (`scripts/pipeline/sonnet/reports/<target_id>.json`) recording:
   - Which fields were filled with real data.
   - Which fields were left as labeled placeholders (and why).
   - Which validation rules passed or failed.
   - The data sources used (internal function names, not raw agency names -- never expose
     source-agency names in user-facing copy; the report is internal-only).

## 6. Placeholder convention (Fable sets it; Sonnet follows it)

Fable marks every unfilled field with a consistent token that Sonnet can find with a grep and
either fill or formalize as a labeled placeholder:

```
FILL:<field_name>
```

For example:
```tsx
narrative="FILL:narrative"
wagesData={null /* FILL:wages_by_role */}
startupCostTotal={null /* FILL:startup_cost_total */}
```

Sonnet's rule:
- If the field has available, validated data: replace `FILL:*` with the real value.
- If the field is data-gated (real data or honest omit, per the master plan): pass `null` or
  omit the prop entirely. The component self-omits gracefully (canonical pattern).
- If the field is architecture-first-placeholder-allowed (country / industry / city new
  sections during the skeleton phase): replace with the Atlas labeled-placeholder string:
  `"[data not yet available for this region]"`. These are honest, they are not fake numbers.

Under no circumstance does Sonnet invent a number, interpolate a value that looks real, or
pass a fabricated figure as if it were measured data.

## 7. Data-fill rules by field type

### 7.1 Financial fields (margins, revenue, owner take-home, wages, startup costs)

**Source precedence (in order):**
1. Trusted-local cell: a row in the `cells` Supabase table with `trust_tier = 'trusted-local'`
   for the exact `(industry_slug, place_slug)` pair. Use it directly.
2. Extrapolated aggregate: a row produced by `src/lib/cells/extrapolated_aggregation.ts` for
   a broader geo (state, region, country). Permitted for display if the component accepts it
   and the data is labeled as extrapolated (the `is_extrapolated` flag). Never strip the flag.
3. Industry baseline: the global or country-level baseline from
   `src/lib/qa/industry_baselines.ts`. Labeled as baseline.
4. No data: pass `null`. The component self-omits. Do not fill with a placeholder number.

**Distinctness guard:** before writing a financial cell, compare the key numbers to
`DISTINCTNESS_THRESHOLD` (defined in `scripts/pipeline/sonnet/config.ts`, default: any two
cells for the same industry in the same country must differ by at least 5% on revenue or
margin). If two cells are identical within the threshold, flag the pair in the fill-report
and do not write the duplicate; return the first as canonical.

**No absolute rankings across mixed axes:** never emit a "top 10 places for bakeries" list
that mixes city-level and country-level data. Like-for-like only (same geo tier, comparable
economic bracket). This mirrors the master plan rule.

### 7.2 Narrative copy fields (the story, the honest take, the plain-terms translation)

**Source precedence:**
1. Existing entry in `src/lib/content/narratives.ts` or `src/lib/content/comparative_narratives.ts`
   for this target. Use it as-is.
2. Generate new copy in Atlas voice (sharp, plain, operator-language, no metaphors, no em-dashes,
   no consultant-speak, no source-agency names). The copy must be grounded in the actual data
   values being filled on the same iteration -- never generic filler. For the narrative field,
   one to three sentences is the right length.
3. For the `HonestTakeBox` field specifically: derive from the margin tier and the cost
   structure. Thin margin + high rent = "this works if you own the building or can negotiate
   a turnover lease." Do not flatter. Do not badmouth. One plainspoken sentence.

**Quality bar for generated copy:**
- Does it read like a person who has seen the numbers? Yes/no check.
- Does it contain any em-dash? Fail if yes.
- Does it name a source agency? Fail if yes.
- Is it longer than 60 words for a single narrative field? Warn.
- Does it contain a metaphor? Flag for human review.

### 7.3 Wage fields

Use `src/lib/economic_profile/wages.ts` and `src/lib/economic_profile/city_wages.ts`. Pass
the resolved value. If `null` is returned, pass `null` -- the component self-omits. Never use
a global average as a local wage without the `is_extrapolated` flag.

### 7.4 Startup cost fields

Use `src/lib/finance/fixed_costs.ts` and `src/lib/cost_engine/engine.ts`. For cities without
local rent data, use the country-level multiplier from `src/lib/qa/city_rent_multipliers.ts`
applied to the industry baseline. Label the result as extrapolated.

### 7.5 Seasonality fields

Derive from `src/lib/cells/trend_synthesizer.ts`. If the series has fewer than 4 real data
points for this target, pass `null`. No fake seasonality curves.

### 7.6 Neighbor / peer comparisons (city-vs-city, country-vs-neighbours, business-nearby)

Like-for-like guard:
- Same page-type axis (city vs city, country vs country).
- Same economic tier (defined in `src/lib/scores/geo_verdict.ts` -- do not compare a G7
  capital to a frontier-market city).
- Same industry (for business-nearby comparisons).
Reuse the `compare_verdict.ts` logic already built for the homepage.

### 7.7 Tourist vs local split, commercial rent, best-areas-to-set-up

These fields are real-data-gated. Show only where data is solid. Self-omit otherwise.
No placeholders pretending to be data. No invented percentages.

## 8. Per-iteration validation checklist

Before writing any output, the loop runs these checks. All must pass or the iteration is
skipped and the failure is logged to the fill-report.

1. **Template integrity.** The Fable template parses (TypeScript compiles). No structural
   sections are missing. The prop types match the domain types in `src/lib/types/`.

2. **No raw values.** The output contains no raw hex codes, no raw pixel values, no raw ms
   durations. Tokens only.

3. **No em-dashes.** The output contains no `--` or `—` in user-visible strings.

4. **No source-agency names.** The output contains no "Eurostat," "BLS," "ATO," "ONS,"
   "OECD," or any data-authority name in user-facing strings.

5. **No fabricated numbers.** Every numeric field traces to a known source (trusted-local,
   extrapolated+labeled, baseline+labeled, or `null`). The fill-report must record the source
   for every non-null numeric field. If the source is unknown, the field must be `null`.

6. **Distinctness guard passed.** See Section 7.1.

7. **Like-for-like guard passed.** No comparison mixes geo tiers or business types.

8. **Narrative quality.** The narrative fields pass the copy quality bar (Section 7.2).

9. **Self-omit confirmed.** Every field passed as `null` is handled by the receiving component
   (i.e., the component returns `null` on null input, per the canonical pattern). The loop
   checks this by inspecting the component's prop types for `| null` or `| undefined` on each
   field it nulls out.

10. **Fill-report written.** The fill-report JSON exists and is valid before the output is
    committed.

Failures are non-fatal for the loop: log, skip, continue with the next target.

## 9. Fan-out across the catalog

The target catalog is the full cross-product of geographies, business categories, and page
types that Atlas intends to cover. It is generated by the catalog builder
(`scripts/pipeline/sonnet/catalog_builder.ts`) and stored as a queue.

### 9.1 Catalog sources

- **Countries:** all sovereign countries in `src/lib/geo/is_sovereign_country.ts` (~195).
- **Cities:** all cities in `src/lib/cities.ts` with a `city_slug` and a known country_iso.
- **Industries:** all active `industry_slug` values from `src/lib/taxonomy.ts`.
- **Neighborhoods:** all entries in `src/lib/cities/neighborhoods.ts`.
- **Learn articles:** all entries in `src/lib/learn/articles.ts`.
- **Compare pairs:** generated from the intersection of cities with data and industries with
  data, subject to the like-for-like guard.

### 9.2 Priority ordering

The catalog is sorted before queuing. Processing order:

1. **Tier 1 -- big economies, real data available:** countries with a trusted-local cell count
   greater than `TIER1_CELL_THRESHOLD` (default: 50). US, UK, Germany, France, Japan, Australia,
   Canada, Brazil, India. Business pages in these countries go first.
2. **Tier 2 -- major cities:** top 100 cities by population with any cell data.
3. **Tier 3 -- industry pages:** all active industries (architecture-first, skeleton + labeled
   placeholders; no fabrication).
4. **Tier 4 -- country pages:** all countries (skeleton phase; new sections are labeled
   placeholders until data arrives).
5. **Tier 5 -- neighborhoods, learn, compare:** after their parent pages are filled.
6. **Tier 6 -- long tail:** remaining cities, sparse-data countries.

This ordering ensures the pages most likely to be visited first are filled first.

### 9.3 Queue format

Each queue entry is a JSON file in `scripts/pipeline/sonnet/queue/pending/`:

```json
{
  "target_id": "business__restaurants__lisbon-portugal",
  "page_type": "business",
  "industry_slug": "restaurants",
  "place_slug": "lisbon-portugal",
  "country_iso": "PT",
  "tier": 1,
  "template_path": "src/app/[country]/[city]/[industry]/page.tsx",
  "queued_at": "2026-06-12T00:00:00Z"
}
```

When an iteration starts, the entry moves from `pending/` to `in_progress/`. On success, to
`done/`. On failure, to `failed/` with the error appended. This is the resume mechanism: on
restart, the loop skips `done/` and `in_progress/` (in_progress is retried after a configurable
staleness window, default 30 minutes).

## 10. The loop itself

### 10.1 Script entry point

`scripts/pipeline/sonnet/run_loop.ts`

```
Usage:
  npx tsx scripts/pipeline/sonnet/run_loop.ts [options]

Options:
  --tier <1-6>          Process only this tier (default: all, priority order)
  --target <id>         Process one specific target_id (dry-run friendly)
  --dry-run             Resolve + validate but do not write output
  --concurrency <n>     Parallel iterations (default: 1; increase with caution on Windows)
  --max-iterations <n>  Stop after n iterations (default: unlimited)
  --from-tier <n>       Skip all tiers below n
  --only-type <type>    business | city | country | industry | neighborhood | learn | compare
```

Example: fill the first 50 tier-1 business pages in dry-run mode to verify output quality
before writing:

```
npx tsx scripts/pipeline/sonnet/run_loop.ts --tier 1 --only-type business --max-iterations 50 --dry-run
```

Example: fill a single target interactively:

```
npx tsx scripts/pipeline/sonnet/run_loop.ts --target business__restaurants__lisbon-portugal
```

Example: run the full loop unattended:

```
npx tsx scripts/pipeline/sonnet/run_loop.ts
```

The loop logs each iteration's outcome to stdout (one line per target: `DONE`, `SKIP`, or
`FAIL [reason]`) and to `scripts/pipeline/sonnet/logs/run-<timestamp>.log`.

### 10.2 Per-iteration steps (the inner loop)

For each target popped from the queue:

```
1.  Move queue entry to in_progress/.
2.  Load the Fable template for this page_type.
3.  Build the data context: call the relevant src/lib/ accessors for this target.
4.  Run the per-iteration validation checklist (Section 8).
    -- If any hard failure: log, move to failed/, continue.
5.  For each FILL: field in the template:
    a. Resolve the value from the data context (Section 7).
    b. Apply the placeholder convention if no real data.
    c. Record the source in the fill-report.
6.  Run the validation checklist again on the filled output (post-fill pass).
    -- If any hard failure: log, move to failed/, continue.
7.  Write the output (unless --dry-run).
8.  Write the fill-report JSON.
9.  Move queue entry to done/.
10. Log: DONE <target_id> [n fields filled, m placeholders, k nulled].
```

### 10.3 Configuration

`scripts/pipeline/sonnet/config.ts` holds all thresholds in one place:

```typescript
export const DISTINCTNESS_THRESHOLD = 0.05; // 5% minimum difference
export const TIER1_CELL_THRESHOLD = 50;      // cells to qualify as tier-1 country
export const NARRATIVE_MAX_WORDS = 60;       // narrative field length warning
export const INPROGRESS_STALENESS_MS = 30 * 60 * 1000; // 30 min before retry
export const DEFAULT_CONCURRENCY = 1;
export const SONNET_MODEL = "claude-sonnet-4-6"; // the model for copy generation
```

## 11. Copy generation (the Sonnet LLM invocation)

For fields that require generated copy (narrative, honest take, plain-terms translation,
first-year story), the loop makes a structured LLM call to the Sonnet model. It does not
call the model for any numeric field; those are resolved entirely from `src/lib/` functions.

### 11.1 Prompt structure (per field)

```
System: You are the Atlas copy engine. You write short, plain copy for marginatlas.com
in the Atlas voice: a sharp friend with the numbers. Warm, precise, operator-language.
No metaphors. No em-dashes. No source-agency names. No consultant-speak. Never fabricate
a number.

User: Write a <field_name> for a <page_type> page.
Target: <industry_name> in <place_name>.
Real data in context: <data_context_json>.
Field definition: <field_definition from the content map>.
Maximum length: <max_words> words.
Return only the copy string, no explanation.
```

The `data_context_json` contains only the resolved numeric values for this target (from the
trusted-local / extrapolated / baseline resolution chain). The model is grounded in real
numbers; it does not have to invent them.

### 11.2 Copy validation (post-generation)

After each LLM call, the loop runs the copy quality checks from Section 7.2 as a simple
regex + word-count pass. If any check fails, the loop retries once with a correction prompt.
If the second attempt also fails, the field is set to `null` (self-omit), logged in the
fill-report as `copy_generation_failed`, and the iteration continues.

### 11.3 Batching LLM calls

If a target has multiple copy fields (e.g., a business page has `narrative`, `honest_take`,
`plain_terms`, `first_year_story`), the loop sends them as a single structured request with
one field per item in a JSON array. This reduces round-trips without losing per-field
validation.

## 12. How the loop stays complementary to Fable

The boundary is enforced by three rules:

**Rule 1: Templates are read-only inputs.**
The loop reads the Fable template but never writes to it. If the loop needs a new prop, a new
section, or any structural change, it appends the gap to `docs/brand/_pipeline/contract-gaps.md`
(the single shared escalation channel named in the Fable handoff contract) and skips the
target. The Fable pipeline triages gaps at the top of each subsequent run.

**Rule 2: The design system is a hard dependency, not a variable.**
The loop imports from `src/lib/design-tokens.ts` to validate that any values it writes are
token-legal. It does not write CSS classes, style attributes, or motion values. All visual
decisions were made upstream in Fable.

**Rule 3: The fill-report is the handshake.**
Every filled page has a fill-report. Fable can read fill-reports to understand which fields
are real-data vs placeholder-vs-null, and adjust the template's fallback UI accordingly. The
fill-report is the contract that lets both pipelines evolve without stepping on each other.

## 13. Resume and scale

**Resume:** restart `run_loop.ts` at any time. It reads the queue state from `pending/` and
`failed/` (retrying failures once by default), skips `done/`, and continues. No manual
intervention needed.

**Scale-up:** set `--concurrency` to a value above 1 for parallelism. On Windows, keep it
at 2-3 (the same Windows-concurrency caution that applies to prebuild). On Linux/Mac servers,
4-8 is safe. The queue directory provides locking: move-to-in_progress is atomic on most
filesystems.

**Incremental runs:** as new Fable templates land, run `catalog_builder.ts --diff` to add
only the new targets to the queue without re-queuing done entries. The diff compares the
current set of Fable templates against `done/` records.

**Monitoring:** `scripts/pipeline/sonnet/stats.ts` prints a summary:

```
npx tsx scripts/pipeline/sonnet/stats.ts

Pending:    1,247 targets
In-progress:   0
Done:          892 targets
Failed:         34 targets  (view: failed/)
Coverage:   41.7% of catalog
```

## 15. Definition of done (per target)

A target is done when:
1. All `FILL:` markers are gone from the output.
2. Every numeric field has a traceable source (trusted-local / extrapolated+labeled /
   baseline+labeled / null).
3. Every copy field passes the Atlas voice quality bar.
4. No fabricated numbers. No em-dashes. No source-agency names. No raw tokens.
5. The fill-report exists and records sources for all non-null fields.
6. The queue entry is in `done/`.

A page is NOT done if any `FILL:` marker remains in the output. Unresolved fields must be
`null` or a labeled placeholder string; never a bare marker in production.

---

## 16. What this pipeline explicitly does NOT do

- Does not redesign sections or add new components.
- Does not change component order or page structure.
- Does not write CSS, Tailwind classes, or token values.
- Does not rename slugs (SEO equity is inviolable).
- Does not run `npm run build` or `npm run prebuild` without the founder's permission.
- Does not fabricate data. Period.
- Does not use the Fable model (claude-opus-*) for bulk replication. Fable is expensive and
  opinionated; Sonnet is fast and precise. Bulk copy generation uses `claude-sonnet-4-6`.
- Does not write to `src/components/`, `src/styles/`, or `src/lib/design-tokens.ts`, and does
  not author or restructure any `page.tsx` template (that is the design layer; Fable owns it).
  The only `src/` writes Sonnet may make are to the narrow pre-existing content accessors named
  in section 5 (e.g. `src/lib/content/narratives.ts`, `src/lib/cities/neighborhood_flavor.ts`).
- Does not push to production directly. Output is committed to a branch; the normal Vercel
  preview + common-sense pass + founder review gate applies for high-stakes surfaces.

## 17. First run checklist (getting started)

Before running the loop for the first time:

1. Confirm at least one Fable template exists and is merged to main for the target page type.
2. Run `catalog_builder.ts` to generate the initial queue.
3. Run `run_loop.ts --dry-run --tier 1 --max-iterations 5` on 5 tier-1 business pages.
4. Open the 5 fill-reports. Confirm: no fabricated numbers, no missing sources, copy quality
   passes. Adjust `config.ts` thresholds if needed.
5. Show the founder 3 filled pages on a Vercel preview branch before bulk-running tier 1.
6. If the preview looks right: run `run_loop.ts --tier 1` unattended.
7. After tier 1: `stats.ts` pass, review a random 5% sample, then unlock tiers 2-6.
